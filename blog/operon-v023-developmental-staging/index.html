Operon v0.23: Developmental Staging

Critical Periods, Capability Gating, and Teacher-Learner Scaffolding

Bogdan Banu · March 2026 · github.com/coredipper/operon

Release: v0.23.0
Abstract

v0.22 added cognitive modes, sleep consolidation, social learning, and curiosity. v0.23 adds the developmental layer: organisms progress through four maturity stages, tool access is gated by stage, critical periods close permanently as the organism matures, and mature organisms scaffold younger ones. This is the penultimate phase of the roadmap, replacing uniform capability sets with staged maturation.

1. The Four Stages

The DevelopmentController wraps a Telomere and maps the fraction of telomere consumed to one of four stages:

StageConsumedPlasticityCharacter
EMBRYONIC<10%1.0Maximum learning, minimal capabilities
JUVENILE10–35%0.75Basic capabilities enabled
ADOLESCENT35–70%0.5Most capabilities available
MATURE>70%0.25Full capabilities, reduced plasticity

Stage transitions are monotonic: even if an organism’s telomeres are renewed (the equivalent of telomerase activity), its developmental stage never regresses, matching the irreversibility of biological maturation.

2. Critical Periods

CriticalPeriod frozen dataclasses declare time-limited learning windows. Each period specifies when it opens and when it permanently closes: 

CriticalPeriod(
    name="rapid_learning",
    opens_at=DevelopmentalStage.EMBRYONIC,
    closes_at=DevelopmentalStage.JUVENILE,
    capability="fast template adoption from peers",
)

Once the organism passes closes_at, the window closes permanently. This mirrors biological critical periods in which specific kinds of learning only happen during bounded developmental windows, such as phonetic discrimination and language acquisition in infants or imprinting in birds.

3. Capability Gating

The Plasmid frozen dataclass gains a min_stage field. When a stage attempts to acquire a tool via Mitochondria.acquire(), the system checks whether the organism’s current developmental stage meets the minimum requirement. An embryonic organism cannot acquire a tool marked min_stage="adolescent".

Preventing Premature Tool Access

Exposing high-impact tools before an organism has built up a reliable pattern repertoire is a predictable failure mode: mistakes compound much faster when an uncalibrated agent has full permissions. Stage gating brings new capabilities online only as the organism accumulates experience.

4. Teacher-Learner Scaffolding

SocialLearning.scaffold_learner() lets mature organisms guide younger ones. The teacher exports templates; the scaffolding mechanism filters out templates too advanced for the learner’s current stage, applies a plasticity bonus to the effective trust score (younger learners are more willing to adopt), and delegates to the standard import mechanism.

As the learner matures, the same teacher export admits a wider set of templates: an EMBRYONIC learner might receive only single-stage pipelines, while an ADOLESCENT learner receives multi-stage workflows from the exact same scaffolding call.

5. Roadmap Status

With v0.23, the first seven phases of the roadmap are complete, spanning five architectural layers:

  1. Structure (v0.17–0.18): typed wiring, topology advice
  2. Memory (v0.19–0.20): bi-temporal facts, auditable substrate
  3. Adaptation (v0.21): pattern library, watcher, adaptive assembly
  4. Cognition (v0.22): cognitive modes, sleep consolidation, social learning, curiosity
  5. Development (v0.23): critical periods, capability gating, scaffolding

One phase remains: Phase 8 (release integration and publication), covering cross-subsystem integration tests, paper revisions, and evaluation runs.
