What Happens When You Try to Evolve Your Agent Architectures

Applying Operon’s biological abstractions to architecture search, where random mutation outperformed an LLM proposer
Bogdan Banu · April 3, 2026
operon-ai v0.26.0
Summary
Operon uses biological abstractions (genes, genomes, epiplexity, immune systems) to structure AI agent pipelines. Phases C1–C7 validated these ideas at the organism level. Phase C8 tests whether they also carry over to evolving organisms. As code structure, they hold up well (lossless Genome round-tripping and scale-invariant health monitoring). As optimization algorithms, LLM-guided evolution fails to beat random tournament mutation, leaving structural safety guarantees as the stronger focus.

1. The Question

Operon’s Genome class manages immutable configuration traits for individual agents, tracking genes, mutations, expression levels, and lineage. Phase C8 tests whether the same abstraction can represent organism-level configurations (the modes, models, and thresholds of a multi-stage pipeline) and whether evolving those genomes discovers better architectures.

In biology, the same genetic machinery governs both running an organism and evolving it across generations. If Operon’s abstractions hold up beyond single-agent config, they should work at both levels.

2. What We Built

Genome Mapping

Each CandidateConfig (stage modes, models, visibility flags, and intervention thresholds) maps to a Genome in about 5 lines of flattening logic: mode and model become STRUCTURAL genes, boolean flags become REGULATORY genes, and the round-trip is lossless with no type coercion or special cases.

genome = candidate_to_genome(config)
restored = genome_to_candidate(genome, ...)
assert restored.stage_configs == config.stage_configs  # always True

This is the strongest evidence that the gene abstraction generalizes beyond its original per-agent use case.

Scale-Invariant Health Monitoring

The existing EpiplexityMonitor detects epistemic stagnation using Bayesian surprise over embedding similarity. We extended it with a DistanceProvider protocol so any novelty metric can plug in. In configuration space, ConfigHammingDistance counts field-level mismatches while leaving the core formula untouched, triggering STAGNANT/EXPLORING transitions identically to the embedding path.

This confirms that epistemic health monitoring is scale-invariant: the same mechanism works for token-level stagnation (within an organism run) and configuration-level stagnation (across an evolution loop).

Dual Stall Detection

Config novelty alone never triggered the LLM proposer, because tournament mutations keep producing different configs (high novelty) even when scores flatten out. We added a second trigger for score plateaus (no improvement in best score over N steps); firing either signal switches the loop to the LLM proposer.

The LLM Proposer

When either trigger fires, a Gemini-backed proposer reads the evolution history from the filesystem store (full candidate configs and execution trace metadata) and suggests a new configuration. This follows the Meta-Harness finding that raw filesystem history outperforms compressed feedback.

The abstractions that describe structure (genes, health monitoring, and composition) carried over cleanly. The ones tied to specific dynamics (fixed-point convergence and trust networks) did not, because evolutionary search follows different dynamics than the runtime loops they were built for.

Giving the LLM proposer full filesystem context triples its score over compressed history (0.49 vs 0.15), yet still only edges past tournament mutation (0.49 vs 0.44). Flipping a single field at random and keeping the best candidate performs nearly as well as an LLM inspecting the entire run history.

The Ao et al. Connection
Ao, Gao & Simchi-Levi (2026) prove that without new exogenous signals, delegated multi-agent networks cannot beat centralized baselines. Here the LLM proposer acts as the delegated network and tournament mutation as the centralized baseline. Rich filesystem context adds signal, yet the config search space is small enough that structural reasoning gives little advantage over random exploration.

5. Phase B: Topology Mutations

Next, we extended evolution to mutate topology directly by adding stages, removing stages, and rewiring edges. Candidates carry explicit edges (directed wiring pairs), and a WiringDiagram paired with ResourceAwareExecutor runs stages in parallel groups via DAG layering.

ProposerPhase A (config only)Phase B (topology)
Tournament0.440.60

With topology mutations enabled, tournament mutation improved (0.44 → 0.60) while the LLM proposer degraded (0.49 → 0.36): blind structural edits worked better than reasoned proposals.

The LLM spends its budget optimizing edges that the organism does not fully use, because shared state still leaks across stages. Tournament mutations that happen to add a helpful stage or drop a redundant one improve the pipeline directly.

6. Conclusions

At the meta-level, biological abstractions work as organizing principles for code, while offering no optimization advantage over random mutation.

The Genome mapping, EpiplexityMonitor extension, and DesignProblem wrapping produce clean, composable code, whereas the evolutionary search itself does not beat random mutation. This matches Ao et al.: without a search space that rewards structural reasoning, the multi-agent approach (LLM proposer) cannot dominate the single-agent baseline (tournament).

The main case for biology-inspired agent engineering still rests on structural guarantees: immune systems, epiplexity monitoring, and developmental gating. C8 makes clear that empirical validation belongs on those runtime safeguards rather than on meta-optimization.

We moved the search code out of the core library (operon_ai/convergence/) and into the evaluation harness (eval/meta/). The only C8 addition that stays in the library is DistanceProvider, which extends epistemic health monitoring cleanly to non-embedding spaces.

7. The Categorical Connection

de los Riscos, Corbacho & Arbib (2026) independently developed a category-theoretic framework (ArchAgents) that maps tightly to Operon’s architecture. In their formulation, objects are organism architectures, morphisms are structure-preserving translations (our compilers), and agents are monoidal functors (configured organisms). Phase A explores agents within a fixed architecture; Phase B explores architecture morphisms. The finding that blind morphisms outperform reasoned ones suggests that the categorical constraints on valid mutations are more productive than LLM-generated ones.

8. What’s Next

With architecture evolution out of the way, the next question is whether Operon’s structural safety features actually work in practice:

  • Does the immune system catch more errors than ad-hoc validation?
  • Does epiplexity monitoring prevent more runaway loops than simple timeouts?
  • Does developmental gating prevent premature deployments?

Those are the mechanisms Operon claims provide structural guarantees, and benchmarking them directly is the next step.
