Operon v0.22: The Cognitive Architecture

Cognitive Modes, Sleep Consolidation, Social Learning, and Curiosity Signals

Bogdan Banu · March 2026 · github.com/coredipper/operon

Release: v0.22.0 – v0.22.1
Abstract

v0.21 added adaptive structure to Operon: pattern libraries, watchers, and the feedback loop connecting them. v0.22 builds out the cognitive layer motivated by Dupoux, LeCun, and Malik’s framing of autonomous learning. Stages can now declare whether they are System A (observational) or System B (action-oriented). A sleep consolidation cycle replays successful runs, compresses recurring patterns into templates, runs counterfactual checks over corrected facts, and promotes histone marks from temporary to permanent. Organisms can also exchange templates across libraries using trust-weighted adoption, while the watcher adds curiosity signals that escalate unfamiliar inputs from fast to deep models.

1. Cognitive Modes: System A/B as Stage Annotations

Operon’s fast/deep nucleus split started as cost routing: send routine work to a small model and harder work to a large one. v0.22 adds an explicit cognitive annotation on top of it. The CognitiveMode enum marks each stage as either OBSERVATIONAL (System A: passive sensing and information gathering) or ACTION_ORIENTED (System B: active decision-making and goal pursuit). 

from operon_ai import CognitiveMode, SkillStage

SkillStage(name="classifier", role="Router", mode="fast",
           cognitive_mode=CognitiveMode.OBSERVATIONAL)

SkillStage(name="planner", role="Strategist", mode="deep",
           cognitive_mode=CognitiveMode.ACTION_ORIENTED)

When not set, cognitive mode is inferred from the existing mode field (fast → observational, deep → action-oriented). The watcher detects mismatches between declared mode and actual execution model, and mode_balance() reports the System A/B distribution across a run.

2. Sleep Consolidation

SleepConsolidation composes five existing components (AutophagyDaemon, PatternLibrary, EpisodicMemory, HistoneStore, and BiTemporalMemory) into a five-step post-batch cycle:

  1. Prune stale context via autophagy
  2. Replay successful run records into episodic memory with tier promotion (WORKING → EPISODIC)
  3. Compress recurring high-success patterns into consolidated PatternTemplate instances
  4. Run counterfactual replay by diffing bi-temporal corrections since each run and asking whether updated facts would have changed the outcome
  5. Promote frequently accessed ACETYLATION histone marks to permanent METHYLATION

What Consolidation Prevents

Without an offline consolidation pass, raw experience piles up without changing future behavior: pattern libraries grow without pruning or compression, episodic memories decay before promotion, and useful histone marks expire instead of becoming permanent. The sleep cycle turns operational history into durable structure, mirroring what Dupoux et al. describe as offline, imagination-based learning during rest.

3. Social Learning: Horizontal Gene Transfer

The SocialLearning module enables cross-organism template sharing, following the biological analogy of horizontal gene transfer in bacteria. Organism A exports successful templates; Organism B imports them with trust-weighted adoption. 

from operon_ai import SocialLearning, PatternLibrary

sl_a = SocialLearning(organism_id="A", library=lib_a)
exchange = sl_a.export_templates(min_success_rate=0.6)

sl_b = SocialLearning(organism_id="B", library=lib_b)
result = sl_b.import_from_peer(exchange)
# result.adopted_template_ids — which templates B adopted
# result.trust_score_used — trust B has for A

Epistemic Vigilance

TrustRegistry implements epistemic vigilance by maintaining per-peer trust scores via an exponential moving average over adoption outcomes. Trust in a source peer rises when its imported templates succeed, falls when they fail, and blocks adoption altogether once it drops below a configurable threshold.

Provenance tracking records which peer supplied each adopted template so subsequent execution outcomes feed directly back into that peer’s trust score. Over time, the organism filters out noisy peers and keeps adopting from reliable ones.

4. Curiosity Signals: Intrinsic Motivation

The watcher adds curiosity as a new signal source. When EpiplexityMonitor detects EXPLORING status (indicating high embedding novelty on unfamiliar inputs), the watcher emits a curiosity signal. If that value exceeds curiosity_escalation_threshold on a stage using a fast model, the watcher recommends ESCALATE to engage the deep model for closer analysis.

This gives the organism a concrete form of intrinsic motivation: instead of answering unfamiliar inputs with a fast model’s cheap pass, it spends deeper compute when novelty spikes. Curiosity is filed as an epistemic signal (same category as epiplexity) with source="curiosity", extending the epistemic category without changing the watcher’s three-category taxonomy.

6. What Comes Next

With the cognitive layer in place, two phases remain on the roadmap: Phase 7 covers developmental staging (critical periods, capability gating, and telomere-based maturation), and Phase 8 covers release integration (cross-subsystem tests, bi-temporal memory adapters, paper revisions, and evaluation runs).

Across the full roadmap, the stack runs six layers deep: structure (v0.17–0.18) → memory (v0.19–0.20) → adaptation (v0.21) → cognition (v0.22) → development (v0.23) → publication (v0.23.x). Each layer builds on the stability of the ones below it; sleep consolidation, social learning, and curiosity signals all rely directly on the adaptive loop, pattern library, and watcher introduced in v0.21.
