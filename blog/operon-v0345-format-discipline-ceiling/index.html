When Your Diagnostic Beats Your Result

We built a patch-apply pipeline to separate model errors from harness failures in Phase 2. The score stayed at zero, but the bottleneck became attributable.
Bogdan Banu · April 17, 2026
operon-ai v0.34.5

What Phase 2 left ambiguous

Two weeks ago we ran SWE-bench Phase 2 and got 0/30 across baseline, organism, and LangGraph on SWE-bench-lite, which we framed as a model-capability ceiling. The problem was that 28 of those 30 submissions never reached a test verdict at all: git apply rejected them first. The model produced text that looked like diffs, and the harness refused to apply them.

That mixes two failure modes:

  1. The model selecting the wrong file path (or inventing one that doesn’t exist in the target repo).
  2. The model writing hunk headers and bodies that git apply can’t consume: placeholder line numbers, mismatched counts, or paths with the repo name doubled.

If most failures fall into (1), grounding the prompt in the actual repository should fix them. If they fall into (2), grounding will not help because the bottleneck is diff-format discipline. The original write-up couldn’t separate the two, so we couldn’t tell which fix mattered.

v0.34.5 adds the instrumentation to separate them. The headline number is still bad (slightly lower on evaluated count, in fact), but the failure mode is now attributable.

The patch-apply pipeline

1. Patch sanitizer

eval/_patch_sanitizer.py sits between extract_patch() and the harness. It runs four passes over each candidate diff:

  • Path normalization. The model often emits --- a/django/django/forms/foo.py for repo django/django, doubling the repo name onto the real path. The sanitizer strips one django/ when the repo name and owner segment match, or strips the full {owner}/{repo}/ prefix when they differ. The same logic runs on diff --git, rename from/to, and copy from/to lines, since partial normalization leaves inconsistent old/new paths that still fail to apply.
  • Placeholder hunk rejection. Hunk headers like @@ -XXX,10 +XXX,10 @@ get rejected. git apply would refuse with a cryptic “missing line number” message; the sanitizer catches it earlier and returns "".
  • Hunk body validation. For each @@ -a,b +c,d @@, the sanitizer walks the body and checks that additions plus context equal d, and deletions plus context equal b. Truncated or overlong hunks (such as declaring 10 lines when the body has 7) get rejected. After a long review chain on this code (more on that below), the validator is count-driven: it consumes exactly the declared body length, so adversarial body content shaped like file headers (--- a/foo.py as the deletion of a line whose content starts with -- a/foo.py) can’t fool it.
  • Bare-empty context repair. Whitespace-stripping editors sometimes turn a single-space context line into an empty line. git apply rejects bare empty lines in hunk bodies; the sanitizer rewrites them back to " " before validation.

The contract is simple: if sanitize() returns a non-empty string, git apply receives a structurally valid diff. If it returns "", the harness records empty_patch rather than conflating malformed model output with an infrastructure error.

2. Repository grounding

--grounding enables a second pipeline. For each instance, the script shallow-clones {repo}@{base_commit} via git fetch --depth 1 origin {sha} into .cache/swebench/{owner}__{repo}-{commit12}/. A heuristic ranker then mines problem_statement + hints_text for plausible identifiers (.py paths, CamelCase class names, snake_case functions), walks the repo, and ranks Python files by stem-match (+3) and path-match (+1). The top 5 candidate files have their first 200 lines injected into the prompt as a Repository context block.

For organism and LangGraph, the same context flows through every stage: SkillOrganism.run(task) passes task unchanged to each stage’s prompt, so injecting context once reaches localize, edit, and verify.

The sanitizer also receives a tree oracle. When it sees a path missing from the cloned tree, it attempts to fuzzy-correct to a unique basename match (e.g. the model wrote django/settings.py instead of a nested path like django/conf/global_settings.py; if exactly one settings.py exists in the tree, the sanitizer rewrites it). If the basename has zero or multiple matches, it rejects the patch. Per-file-diff state lets create, rename, and copy targets pass through unchanged, since a newly created file will not exist at base_commit.

3. Failure-mode classification

Two additions to the results artifact keep failure modes distinct:

  • EVAL_RUNTIME_ERROR separates runtime failures from sanitizer-rejected empty_patch entries. When a model call raises (Ollama API timeout, network glitch, OOM), the prediction carries an error_reason field. classify_prediction(error_reason, harness_status) unconditionally overrides any harness verdict to runtime_error when error_reason is set (including not_evaluated under --skip-harness and harness-reported error), because the harness cannot see client-side exceptions.
  • mean_latency_ms divides by completed predictions rather than n. Before this fix, two timeouts on a 10-instance run deflated the baseline mean by 25%.

We also added a CLI mode to refresh envelopes after the fact: python -m eval.swebench_phase2 --rewrite-envelope eval/results/swebench_phase2.json re-resolves the model identity against live Ollama, recomputes the post-run digest check, and rewrites the envelope through the same writer the live run uses. It reads the verification tag from the artifact rather than --model, so a stale CLI default can’t silently verify the wrong model.

Sidebar: nine roborev iterations on the diff parser. The patch sanitizer’s diff parser went through nine code-review rounds (#724 through #748) before converging. Every round hit the same problem: shape-based heuristics for telling file headers apart from hunk-body lines kept failing on adversarial content. Switching to count-driven hunk consumption fixed it. Inside a hunk body, a --prefixed line is always a delete regardless of what follows it; shape checks return only at boundaries between hunks, and only as a full ---/+++/@@ triplet for bare multi-file diffs. When parsing untrusted input, length-prefixed sections hold up where delimiter matching breaks, and unified diffs give you line counts for every hunk body as long as the parser actually tracks them.

Every error from the original run collapsed to either sanitizer-rejected or runtime-error. The sanitizer’s pre-rejection means no malformed patch reaches the harness anymore, so what previously appeared as 20 application failures is now correctly attributed to the model.

The single survivor: django/django-11001 baseline reached the harness as unresolved (the patch applied cleanly, though tests still failed). That is the same instance that survived in the original run, suggesting that something about the issue’s structure (likely a small, localized hunk) makes it easier for a small model to format cleanly. It is the only positive control we have.

Localizing the bottleneck

Grounding solves failure mode (1). Every prompt now contains the actual files at base_commit, the sanitizer’s tree oracle catches near-miss paths, and the heuristic ranker reliably surfaces the right files (smoke-tested on a real astropy issue: all 5 candidate files came from astropy/modeling/ for a modeling problem).

Even with the right files in the prompt, 27 of the 28 submissions that returned output were still rejected by the sanitizer for placeholder hunk headers, mismatched header counts, or paths missing from the cloned tree. That localizes the bottleneck to (2): at 8B / Q4_K_M, the binding constraint is the model’s ability to emit format-correct unified diffs rather than file selection.

Unlike the original run, this gives a concrete capability bound instead of an inconclusive result, and we retitled Paper 5 §6.3 accordingly: 8B Format Discipline Is the Ceiling.

Side observations

The organism format leak closed

The original run had a 4-vs-0 empty_patch gap between organism and baseline because the three-stage pipeline leaked critique prose into the diff slot. Phase A’s tightened [edit]-stage instruction (“your entire response for this stage must be a single fenced diff block and nothing else”) eliminated that leak. In the grounded rerun, baseline and organism converge in the wrong direction across the 8 non-timeout cases (baseline gets one patch through while organism gets 0), consistent with localize/edit/verify forcing the model to maintain strict diff formatting while juggling intermediate stage outputs, a tax that single-shot prompting avoids.

Grounding is overhead at 8B

Baseline mean latency rose from 44s in the original run to 131s with grounding; organism went from 88s to 170s, and langgraph from 90s to 172s. The 30 KB of repository context per prompt roughly doubles to triples per-call wall-clock time, with zero compensating gain in evaluated instances. With stronger models where format discipline isn’t the binding constraint, real file context should translate into better patches, but at 8B it is pure overhead.

Two API timeouts

Two of the 30 model calls (both baseline, on astropy-12907 and astropy-14995) timed out at the OpenAI-compatible client’s default. The exception-handler path constructed empty-patch predictions with latency_ms=0.0. In an earlier draft, those were serialized as empty_patch indistinguishable from sanitizer rejections, and mean latency divided by 10 instead of 8. Code review caught it (Roborev #747). The fix was the EVAL_RUNTIME_ERROR status with explicit error_reason; the test suite now pins those two failed rows so a regeneration can’t silently drop them.

Those two instances also failed under organism and langgraph, both of which completed normally. The timeouts therefore don’t weaken the format-discipline claim: the model produced no usable diff for either instance under any condition.

Scope of the result

What this run establishes is narrow: at 8B / Q4_K_M, emitting git apply-clean unified diffs is the binding constraint on SWE-bench-lite resolution. Three-stage decomposition does not ease that constraint (if anything, it adds a formatting tax), and putting the actual files in the prompt does not ease it either.

This does not show that the organism architecture is intrinsically worse than direct prompting, since a 1-vs-0 difference in evaluated patches is too small to discriminate. Nor does it mean grounding is overhead in general; the same context pipeline should add real value once format discipline is no longer the bottleneck.

It also leaves the categorical harness’s structural guarantees untouched. Certificate preservation across compilers (Paper 5 §5), priority gating, and stagnation detection are Know-level properties verified independently of SWE-bench task resolution.

Diagnostics before fixes

You have to isolate the failure mode before trying to fix it. Phase A and Phase B did not improve the headline SWE-bench-lite score, but they converted an ambiguous error bucket (which conflated model failures with infrastructure failures) into distinct empty_patch rejections with reason codes and separate runtime_error statuses. Follow-up runs with stronger models, format-correction retry loops, or RL on diff format now have a clean baseline to measure against.

Agent evaluations tend to treat the resolved rate as the only result that counts. When that rate is zero for ambiguous reasons, the useful output is the instrumentation that tells you why and sets up a clean next experiment.

What’s next

Three candidate follow-ups, ordered by how likely they are to change the result:

  1. Stronger model. Run the same code with --model qwen3:latest, or move past the 8B class to a 70B+ model on Modal or RunPod. Format discipline scales with model size and training, so bigger models tend to clear this bottleneck first.
  2. Format-correction retry. Re-prompt the model on sanitizer rejection with the specific failure reason (“your hunk header had XXX placeholders; please use real line numbers from the file shown above”). This doubles cost per failure, though it might recover 20–40% of sanitizer drops. It requires a runner change and is not shipped yet.
  3. LLM-localized candidate ranking. Reuse the organism’s localize stage as the file ranker for baseline too. Because the heuristic ranker already surfaces plausible files, any gain here is likely marginal.

None of these require further harness changes; they all run on the v0.34.5 patch-apply pipeline.

Summary

v0.34.5 ships a reusable patch-apply pipeline (sanitizer, grounding, and failure classification) along with a baseline establishing the format-discipline ceiling for our local 8B model. The resolved count is still zero, and the infrastructure worked as a diagnostic rather than a score improvement. The next experiment is a model swap.
